# 보안 및 성능 점검

점검일: 2026-09-19

## 확인한 문제와 조치

| 구분 | 확인한 문제 | 조치 |
| --- | --- | --- |
| 브라우저 방어 | 스크립트 출처 제한, 프레임 삽입 방지 등 응답 헤더 누락 | CSP, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy 추가 |
| 화면 문자열 | API 및 저장 데이터의 일부 값이 innerHTML로 삽입됨 | textContent, DOM 노드, DocumentFragment로 교체 |
| API 오류 | 외부 조회 예외의 내부 메시지가 응답에 포함됨 | 사용자에게 고정된 오류 안내만 반환 |
| API 입력 | 중복 또는 불필요한 쿼리와 크기에 명시적 제한 없음 | 허용 키/값, 길이, 항목 수, 중복 검사 후 잘못된 요청은 400 |
| 동시 요청 | 캐시가 없을 때 같은 지수의 외부 조회가 중복됨 | 지수별 잠금과 잠금 획득 후 캐시 재검사; 성공한 동시 조회 공유 |
| 렌더링 | 동일 데이터에서 만기일 제외 설정만 바꿔도 차트 재생성 | 같은 데이터의 차트 인스턴스 재사용 |
| 브라우저 저장본 | 잘못된 형식의 저장 데이터가 화면 로딩을 방해할 수 있음 | 저장본 및 원본 응답 구조 검사, 손상된 저장본 폐기 후 재조회 |
| 정적 파일 | HTML에 모든 앱 스크립트와 스타일 포함 | 별도 파일로 분리; HTML 약 47.6KB에서 9.8KB로 감소 |
| 라이브러리 캐시 | 고정 버전 파일의 장기 재사용 정책 없음 | 버전이 명시된 3개 라이브러리 파일에 1년 immutable 캐시 |

## 검증

- Python 19개 및 JavaScript 8개 테스트 통과.
- 일반 요청과 강제 새로고침 각각 5개가 겹치는 테스트에서 외부 조회 1회 확인.
- 순차적인 새로고침은 각각 원본을 조회하며, 예외 후 잠금 해제 확인.
- 브라우저에서 악성 HTML 형태의 문자열이 텍스트로 표시되고, 인라인 스크립트는 CSP에 차단됨을 확인.
- 손상된 저장 데이터 복구, 정상 화면의 CSP 위반 없음, 차트 인스턴스 재사용 확인.
- 실제 휠/드래그/터치 확대 및 이동, 5거래일 최소 범위, 새로고침 후 범위 유지, 최신순 표, 모바일 배치 회귀 검증.
- 공개 사이트의 `.env`, `.env.local`, `.git/config`, 내부 Python 모듈 및 KRX 저장본 URL은 404 응답.
- 앱 파일의 알려진 비밀값 형식 검사에서 노출 후보가 발견되지 않음. 비밀값 자체는 출력하거나 보고서에 기록하지 않음.
- OSV에서 Chart.js 4.4.3, chartjs-plugin-zoom 2.2.0, Hammer.js 2.0.8, lucide-static 0.468.0을 조회했으며 해당 검사 시 알려진 취약점 항목이 반환되지 않음.

## 범위와 남은 한계

- 공개 화면, API 경로, 소스 및 포함된 라이브러리를 대상으로 한 제한적 점검이며, 전체 침투 테스트나 보안 보증은 아님. 알려진 취약점 검색 결과는 이후 달라질 수 있음.
- HTML 삽입 경로는 방어적으로 제거한 것이며 외부 공격자가 실제 데이터를 통제할 수 있음을 입증한 것은 아님.
- 동시 조회 공유는 같은 프로세스와 지수에 한정됨. 여러 Vercel 인스턴스에 걸친 공격성 반복 새로고침 제한은 별도의 공유 저장소 또는 플랫폼 방화벽 설정이 필요함.
- 원본 조회 실패 시 오류/오래된 대체 데이터를 정상 캐시로 저장하지 않음. 외부 공급자의 장애와 요청 제한 자체를 제거하지는 못함.
- 이전에 추가한 KRX 저장본 갱신은 별도 실행 작업이며 자동 갱신 일정은 등록되어 있지 않음.
